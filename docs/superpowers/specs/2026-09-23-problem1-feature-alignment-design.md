# 问题 1：原始多模态特征与时序对齐设计

## 目标与边界

对附件 1 的 100 条原始视频构建可复现的文本、语音、视觉时序特征，并将三种模态对齐到每条样本至多 50 个时间槽。交付物必须能从 `video_id + clip_id` 追溯到原视频时间段，满足论文中的全量汇总和典型样本展示要求。

本阶段不训练情感预测模型，不使用附件 1 标签训练任何模型，不修改原始归档，也不把全零数值自动宣称为模态缺失。问题 2、3 的训练仍仅使用附件 2，专项集只用于最终推理。

赛题数据是唯一的情感数据来源。允许的开源工具和预训练模型只用于基础特征提取；其名称、版本、权重标识、参数和本地路径必须写入运行清单。不得额外使用情感数据集训练、微调、选择阈值或统计结果。

## 输入与运行前置

1. 审计产物 `raw_samples.csv` 是附件 1 的唯一样本清单；只有映射状态为 `matched` 且时长成功解析的记录可以进入提取队列。
2. 用户必须显式传入 7-Zip、FFmpeg 可执行文件和本地模型缓存目录。当前运行环境没有这些多媒体和模型依赖，程序必须在预检阶段明确失败，不能生成替代性的伪特征。
3. 文本使用赛题 `label-100.xlsx` 给出的英文转写；本地缓存的 WhisperX `facebook/wav2vec2-base-960h` 直接将该转写强制对齐到视频音频，生成词级时间戳及其在原转写中的字符跨度。赛题转写是唯一的文本内容；流程不加载 Whisper Small 生成转写，也不产生转写匹配日志。

## 方案比较与选择

1. 将整段文本复制到每一个时间步实现简单，但不能证明跨模态对应关系，不采用。
2. 仅保留按秒可变长度序列能保存物理时间分辨率，但后续接口、存储和专项证据定位更复杂，不作为主交付格式。
3. 采用“真实时间锚点 + 固定 50 槽表示”。每一个时间槽仍保存其原视频中的起止秒数，因此既可兼容固定形状建模，也能回查原始片段。此方案为主方案。

## 特征与对齐流程

### 1. 样本与时间轴

对每条视频读取审计确认的持续时间 `D`，构建半开区间 `[(i/50)D, ((i+1)/50)D)`，最后一槽包含终点。所有后续帧、声学窗口和词区间均通过与该区间的重叠比例聚合。每条样本保存 50 槽的实际开始、结束秒数和 `valid_length=50`；遇到无法解码或无法对齐的样本，写入失败日志并保留原始映射记录，不填造成功特征。

### 2. 文本

使用本地缓存的 `bert-base-uncased` 产生 768 维 token 级语义向量。将词级时间戳与 tokenizer 的 offset mapping 对齐，按时间槽均值池化；没有重叠文本的槽由独立 `text_mask` 标记，不把它与模型故障混同。原文、词、token、槽之间的对应关系写入每样本的证据记录。

### 3. 语音

FFmpeg 解码为单声道 16 kHz PCM。以 25 ms 帧长、10 ms 帧移运行 OpenSMILE `eGeMAPSv02` 的低层描述符，按时间槽进行带时间重叠权重的均值和标准差池化，输出配置锁定后的 50 维语音向量。本地不可用时预检失败，不切换为不同语义的特征。

### 4. 视觉

FFmpeg 以 10 FPS 抽帧，使用本地缓存的 MediaPipe Face Landmarker `face_landmarker.task` 提取 52 维面部 blendshape、人脸面积、中心 x/y 与人脸存在标记，共 56 维帧级视觉向量。只有检测到人脸时才输出该帧的向量，其存在标记固定为 `1.0`；Face Landmarker 不提供可用的人脸检测置信度。对同一槽的有效帧池化，记录人脸检测成功率与 `vision_mask`。没有检测到人脸是观察结果，不等价于赛题的局部模态缺失。

### 5. 统一输出

每条成功样本都生成 `text[50, 768]`、`audio[50, 50]`、`vision[50, 56]`，使用 `float16` 存储以控制提交体积；掩码、时间戳和统计信息分别保存，避免以零值承载语义。所有张量维度、dtype、工具版本、模型标识和参数写入版本化契约。

## 产物

输出目录必须是新目录，包含：

- `q1_samples.csv`：100 条样本的映射、时长、提取状态、特征形状、文件路径与失败原因。
- `features/<sample_id>.npz`：单样本三模态张量、掩码及 50 槽时间边界。
- `alignment_evidence/<sample_id>.json`：词、token、音频窗口和视觉帧到时间槽的映射证据。
- `feature_contract.json`：统一字段、dtype、形状、工具版本、模型和配置摘要。
- `run_manifest.json` 与 `run.log`：输入归档指纹、命令、依赖版本、成功和失败计数。
- `typical_sample.md`：从一个成功样本生成的文本片段、时间段、帧索引与特征槽对应表。

中间 WAV、帧图像、模型权重和缓存只放入忽略目录，不能作为提交物。最终产物使用压缩的单样本文件，目标是连同代码与说明保持在赛题 50 MB 上限内；实际大小在交付前检查。

## 错误处理与可审计性

预检失败（找不到工具、模型或配置不完整）直接退出且不创建半成品输出。单样本失败记录到 `q1_samples.csv` 和运行日志，整个运行以非零状态结束，但保留已成功样本和全量 100 条覆盖记录。对赛题转写无法产生有效词级时间戳时，标记为失败而不是猜测时间戳。

## 验证策略

1. 单元测试：50 槽边界、区间重叠池化、词/token 映射、掩码与零值分离、输出契约序列化。
2. 受控集成测试：小型媒体夹具验证 FFmpeg 解码、单样本特征写入、非零错误传播和覆盖记录。
3. 真实 smoke test：先处理 1 条已审计视频并人工检查证据表，再明确运行 100 条全量任务。
4. 验收：`q1_samples.csv` 恰有 100 条记录；每条记录要么成功并关联三个特征与时间证据，要么有可解释的失败原因；典型样本能从槽号回查到原始秒数、文本和帧；运行清单可在同一输入和缓存上复现。
